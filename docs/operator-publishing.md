# 운영자 페이지 발행 안내 (operator publishing)

작성 2026-11-05. 승인 권한이 있는 운영자가 코드 수정·배포 명령 없이 `/admin/` 에서 새 공개 URL(시공사례·증상 가이드·서비스·지역 서비스)을 만들고 공개·수정·비공개하는 절차와, 그 뒤에서 동작하는 시스템을 적는다. 휴대폰에서도 같은 화면으로 작성·업로드·미리보기·발행이 된다.

## 1. 화면 흐름

1. **새 페이지 작성**(관리자 첫 화면 버튼 또는 메뉴) → 유형 선택(시공사례 / 증상 가이드 / 서비스 / 지역 서비스). 유형마다 꼭 채울 입력란과 예시가 표시된다. 지역 서비스는 지역과 서비스를 고르고, 이미 공개된 조합·통합(리디렉션) 중인 주소는 새 글 대신 기존 글 보강을 안내한다.
2. **편집 화면** — 제목, 요약(첫 문단), 유형별 필수 내용, 본문(빈 줄 = 문단, `## ` = 소제목, `- ` = 목록), 사진, 연결(상위 허브·관련 페이지·대표 검색 의도), 검색 결과 표시(제목·설명과 예시 화면), 작성일 표시 여부. 2초마다 자동저장되고 저장 시각이 표시된다. 글쓰기 가이드는 화면 안에 접혀 있다.
3. **발행 전 확인**(오른쪽) — 누락·오류 항목을 누르면 해당 입력란으로 이동한다. 비슷한 글(제목·본문·대표 의도)이 있으면 목록으로 보여 주며, 새 글 대신 기존 글을 보강할지 고른다.
4. **검수 요청**(작성자) → **승인하고 공개**(승인 권한자 admin). 한 사람이 승인 권한도 가지면 같은 화면에서 바로 공개한다.
5. 공개 후 **URL 복사 · 게시물 열기 · 수정 내용 다시 공개 · 비공개 · 검색 발견 준비 재검사 · 이력 복원**. 제목을 바꿔도 주소는 유지된다.

## 2. 상태의 뜻

| 상태 | 뜻 |
|---|---|
| 초안 | 작성 중. 공개 주소는 404 |
| 검수 요청 | 작성자가 승인 권한자에게 넘김. 수정하면 다시 초안 |
| 발행 중 | 공개 처리와 검색 발견 준비 검사가 진행 중(수 초) |
| 공개 및 검색 발견 준비 | 공개됐고 자동 검사(새 주소 200 · 초기 HTML 제목·본문·self-canonical · 사진 200 · 상위 허브 HTML 링크 · 사이트맵 포함) 통과 |
| 공개 오류 | 공개는 됐지만 검사 항목 중 실패가 있음. 항목을 보고 수정 후 "재검사" |
| 비공개 | 주소 404, 사이트맵·허브에서 제외. 내용은 보존되며 다시 공개 가능 |

검색엔진의 수집·색인·노출은 별도 관측 상태다(`docs/search-console-runbook.md`). 발행 완료가 색인을 뜻하지 않는다.

## 3. 사진

- JPEG · PNG · WebP, 장당 15MB(`UPLOAD_MAX_MB`), 한 번에 10장. 파일명은 한글·영문·공백·괄호·`#` 그대로(예 `수원 현장 (전).jpg`, `Door Repair 01.PNG`, `동탄-Sensor #2.webp`). 같은 이름을 다시 올려도 덮어쓰지 않는다. 확장자 대소문자는 구분하지 않는다.
- 실제 파일 내용으로 형식을 판정한다. HEIC/AVIF·GIF·위장 파일은 이유를 안내하고 거부한다. 파일마다 개별 결과가 표시되고 실패한 것만 다시 올릴 수 있다.
- 원본은 `var/uploads/orig/`(비공개, 0600)에 보관하고, 회전을 반영한 뒤 위치정보 등 메타데이터를 제거한 WebP(480/960/1600px, 업스케일 없음)만 `/uploads/{id}-{w}.webp` 로 공개한다. 공개 화면에는 `width/height`·`srcset`·사진 설명(alt)이 붙는다.
- 사진 설명(alt)은 필수다. 실제로 보이는 내용을 쓴다(예: 상가 출입문 상단 안전센서 점검 모습). 삭제한 초안의 사진은 다른 글에서 쓰지 않을 때만 함께 지운다.

## 4. 발행 전 자동 판정(막는 것 / 경고)

- **막음**: 제목 8자 미만, 요약 20자 미만, 실질 본문 300자 미만, 유형별 필수 입력란 누락, 주소 미정·충돌(이미 공개/통합/보류 주소), 공개되지 않은 허브·관련 페이지, 사진 설명 없는 사진, 다른 글과 동일한 본문.
- **경고**(검수에서 해결): 제목의 같은 말 3회 이상 반복, 확인되지 않은 가격·보증·출동 시간 표현, 검색 제목 70자·설명 160자 초과, 비슷한 제목·같은 대표 의도의 글.
- 글자 수·사진 수·키워드 밀도는 순위 공식으로 쓰지 않는다. 예시 문구·임의 수치는 자동으로 글이 되지 않는다.

## 5. 뒤에서 일어나는 일

- 저장소: `var/content/pages.json`(원자적 쓰기) + 이력 `var/content/history/{id}/v{n}.json`. 발행·복원·검사 시점마다 버전이 남는다. 공개 라우트(`/cases/[id]`, `/guides/[gid]`, `/services/[id]`, `/areas/[province]/[rid]/[service]`)는 레지스트리(빌드 시 생성) → 저장소(요청 시) 순으로 찾고 없으면 404 를 돌려준다.
- 발행 시 해당 주소·상위 허브·목록 허브·`/sitemap.xml` 캐시를 재검증한다(`revalidatePath`). 사이트맵은 요청마다 생성되므로 등록한 사이트맵 주소는 고정이다. 허브·상세는 최대 60초 ISR 로도 갱신된다.
- 캐시 재검증은 응답이 끝난 뒤 반영되므로 "검색 발견 준비 검사"는 응답 이후(`after`)에 실행되고 결과가 저장된다. 화면은 1.5초 간격으로 결과를 받아 표시한다(최대 60초).
- 같은 글의 동시 발행·오래된 버전으로의 발행(409)·중복 클릭은 거부한다. 주소 고유 제약은 저장 시 검사한다.
- 발행된 글의 변경 통지(IndexNow)는 `npm run indexnow`(드라이런)로 대상이 계산되며, 실제 전송은 운영자 승인 후 키 설정 시에만 한다. 수동 색인 요청은 장애 진단 등 예외적으로만.

## 6. 권한과 계정

- `ADMIN_USERS="id:email:scrypt-hash:role,…"` — `admin`(승인·공개·비공개 포함 전체), `editor`(작성·사진·검수 요청), `viewer`(열람). 해시는 `node scripts/admin-hash.mjs '<비밀번호>'`. 세션 비밀키 `ADMIN_SESSION_SECRET`.
- 관리자·미리보기·관리 API 는 인증 없이는 로그인으로 보내거나 401 이며 `X-Robots-Tag: noindex`. 초안은 공개 주소로 절대 나가지 않는다.
- 문의 내역 화면은 두지 않는다(2026-11-05 운영자 결정). 문의 폼 접수는 알림 채널(`CONTACT_NOTIFY_WEBHOOK` / `CONTACT_NOTIFY_EMAIL`)로 전달하고 `var/inquiries.jsonl` 은 접수 ID·중복 방지·복구용 백업 기록이다.

## 7. 운영 수용 테스트(재현)

```bash
H=$(node scripts/admin-hash.mjs 'test-pass-1234' | tail -1)
ADMIN_USERS="owner:o@x:$H:admin,staff:s@x:$H:editor" ADMIN_SESSION_SECRET=$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))") npm start
```

```bash
node scripts/publish-acceptance.mjs --base http://127.0.0.1:3000
```

검사 44항목: 한글·영문·혼합 파일명 업로드, NFD→NFC, 같은 이름 재업로드, 위장 파일·HEIC 거부, 자동저장·버전 충돌(409), 필수 누락 목록, 작성자 공개 403·검수 요청, 승인·공개 후 5분 이내 새 URL 200·초기 HTML title/본문/self-canonical·사진 200·원본 비공개·허브 링크·사이트맵 포함, 제목 수정 후 URL 유지·재발행 반영, 이력 복원, 비공개(404·사이트맵 제외·허브 링크 제거·인증 없는 미리보기/API 차단), 재발행. 결과: `reports/publish-acceptance.json`.

## 8. 서버리스·다중 인스턴스 주의

파일 저장소와 `after()` 기반 검사는 **디스크 쓰기가 가능한 단일 Node 서버**(`next start`) 기준이다. 서버리스나 인스턴스가 여러 개인 환경에서는 `src/lib/server/content.ts`·`uploads.ts` 의 읽기/쓰기 함수를 같은 인터페이스로 DB·오브젝트 스토리지 어댑터로 바꿔야 한다(`docs/release-and-rollback.md`).
