# 318개 후보 전수 본문 생성 (content generation)

2026-11-04 사용자(프로젝트 책임자) 지시: 엑셀 318개 후보 전부에 메인 페이지 수준 분량의 고유 본문을 작성해 색인 대상으로 발행. 이 문서는 생성 방식·검증 결과·남는 위험을 기록한다.

## 1. 구성

| 유형 | 수 | 본문 출처 |
|---|---|---|
| 지역×서비스 (`/areas/{seoul\|gyeonggi}/rNN/{repair\|install\|sensor\|motor\|glass-door}/`) | 280 | `src/content/gen/compose.ts` 가 지역 사실(`regions-seoul.ts`·`regions-gyeonggi.ts` 56건)과 서비스 블록(`blocks-*.ts` 5종)을 결정적으로 조합. 수원·평택·화성 수리/설치 6건은 `src/content/regions.ts` 의 근거·FAQ 를 추가로 얹음 |
| 증상·정보 가이드 (`/guides/gNN/`) | 30 | `guides.ts`(G01~06) + `guides-more.ts`(G07~30) 고유 본문 + `guide-details-*.ts`(심화 3문단·FAQ 2) + `guide-extra.ts`(추가 2~4문단) + 관련 서비스 블록(증상·절차·판단·비용·용어) |
| 핵심 서비스 (`/`, `/services/*`, `/areas/{seoul,gyeonggi}/`) | 8 | 수기 본문(`services.ts`) + 건물 유형별 포인트·증상·FAQ·용어·지역 링크 |

지역 사실은 행정 구성(읍·면·동), 대표 권역·상권, 건물 유형(오피스·상가·아파트·빌라·공장·병원·학원·물류·관광·신도시·종교시설)처럼 공개된 일반 사실만 적었고, 지역별 현장 사례·실적은 적지 않았다(실제 사례가 있는 금천·용산·용인·화성·성남·안양·경기광주만 사례 문장 포함). 평택 접근 동선은 일반 도로 기준.

## 2. 고유성 확보 방식

- 섹션마다 4~6개 변형 문단을 두고 `mix(지역 index, 서비스 index, 섹션 salt)` 해시로 선택 → 같은 서비스의 두 지역이 같은 문단을 공유할 확률 ≈ 1/5 per 섹션.
- 지역 고유 요소: 프로필·접근 동선(지역당 1건, 5개 서비스 페이지가 공유), 권역 이름이 들어간 문장(권역 메모·권역×유형 조합·리드·제목·설명), 읍·면·동 목록, 생활권 별칭, 이웃 지역 문장.
- 증상 순서·FAQ 순서·태그 순서를 지역별로 회전시켜 구조도 달라지게 함.

## 4. 발행 상태와 남는 위험

- 대장: 318개 후보 전부 `approved`(검수자 "사용자 지시 2026-11-04"), C-glass-door 포함. 사례 c4~c8 은 여전히 `review`.
- **검색 노출은 보장할 수 없다.** 엔진이 색인·노출을 결정하며, 지역명 조합 페이지는 Google 스팸 정책의 "doorway" 판단 대상이 될 수 있다. 완화 요소는 지역별 공개 사실·권역 고유 문장·낮은 유사도(평균 0.11)이지만, 실제 현장 사례가 없는 지역 페이지는 근거가 약하다. 배포 후 D+14/30/60/90 색인·노출 데이터로 미색인·저품질 사유를 확인하고, 반응이 없는 유형은 통합(`hold`/`merged`)을 검토한다(`docs/search-console-runbook.md`).
- 기술 담당 검수: 가이드 30건의 안전 범위(분해·센서 해제·강제 조작 미안내)는 작성 규칙으로 지켰으나 기술 담당의 최종 검수 기록은 없다. 운영자 확인 항목(보조번호·후기·사례 c4~c8·강화도어 취급 범위 등)은 `docs/owner-approvals.md` 그대로 유효하다.
- 지역 사실의 오류 가능성: 공개 사실 기준으로 작성했으나 상권·행정 명칭 변화가 있을 수 있어 운영자 검토를 권한다(지역 사실 파일 2개만 고치면 280 페이지에 반영).

## 5. 재생성·수정 방법

- 지역 사실 수정: `src/content/gen/regions-*.ts` → `npm run build`.
- 문단 변형 추가: `src/content/gen/blocks-*.ts`, `blocks-common.ts` (변형이 늘수록 유사도는 내려감).
- 분량·유사도 재검증: `npm start` 후 `npm run seo:audit`, `npm run content:dupcheck`. 보고서 `reports/seo-audit.json`, `reports/dup-check.json`.

## 6. 2026-11-05 품질 감사 반영

- 지역 **수리** 페이지에 `04-1 센서·모터·컨트롤러 수리` 절(부품별 증상·조치 카드 3종 + 건물 관리자 사전 점검 문단)을 추가했다. 지역 센서·모터 페이지(110개)는 지역 고유 근거가 없어 이 절로 통합(C, 308)했다. 예외: 금천구 센서(사례 c2)·용산구 모터(사례 c3)는 근거가 있어 유지.
- 서울 지역 페이지에는 `당일 출장` 확약을 쓰지 않는다(`compose.ts seoulSafe`). 운영자 회신은 경기도권 당일만 확인했다.
- 지역 페이지에서 서비스별로 완전히 동일했던 용어 카드(GLOSSARY)를 제거했다(서비스·가이드 페이지에서 제공). 대리점 수·"상담이 많다/수요가 꾸준하다" 류의 근거 없는 빈도 주장도 지역 사실 문장에서 제거했다.
- 내부 링크: 서비스·가이드 페이지의 지역 링크를 전 지역 나열(56개)에서 우선 지역(평택·수원·화성·용인)+근거(A) 지역+광역 허브로 줄였다. 지역 간 탐색은 광역 허브와 지역 페이지의 "주변 지역" 절이 맡는다.
- 측정: `npm run content:audit` 가 렌더링 본문으로 문장 단위 고유/템플릿 비율을 재고 대장 `reviewNotes.metrics` 에 기록한다. 결과와 해석은 `reports/content-quality.md`. 변형 조합 방식의 한계(문장 단위 공통 비율이 높음)는 그대로 기록했고, 지역명만 바꾼 URL 추가는 하지 않는다.
